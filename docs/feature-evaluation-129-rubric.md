# 129 篇四功能专项：计分与实现

用同一批 PDF 比较 `3.1-ft` 和 `3.1-origin`。RSI 验收整份 PDF 的最终 Markdown 及其中可访问的图片。以结构化输出追溯来源页、区域和 `sub_type`。正式配置固定 `MinerU3`、`relevel_titles=true`、`title_rules=false`，按功能切换对应开关。现有 case 分数用于校准，证据来自渲染前 IR（`relevel_applied=false`）。

2026-11-24 的实现收敛、GT 哈希、当前复算结果与离线交接入口见 [评分交付口径](legacy129-scoring-contract.md)。实现版本为 `legacy129-content-v1`。此次未改 GT 或主分公式；新增可读分数报告、明确的分母、证据覆盖、缺项原因与评分源码哈希。`feature_matrix` 的定位／非空计数仍是回归诊断，内容分使用 `feature_rubric`。

## OmniDocBench 的做法

本机 OmniDocBench（`f133a71`）的端到端评测把 Markdown 拆成元素，在页面内和结构化 GT 匹配，再计算各项指标。官方 Overall 是 **文本准确率、表格 TEDS、公式 CDM 各占 1/3**，统一换算到 0–100。阅读顺序也评，作为单列指标。它允许对预测做拆分、合并再匹配，GT 保持固定。依据见 [本机 README 的 Overall 公式](../../OmniDocBench/README.md#L517) 和 [端到端匹配说明](../../OmniDocBench/README.md#L982)。

这套专项沿用「先匹配、再算分、最后等权汇总」。默认文本评测会过滤页眉、页脚、页码，图形本体也不在该文字匹配池中。因此四项要各用自己的 GT 和指标。图表的判分单元是带系列、类别及单位的值，表格行列能调整，错列错单位要扣分。依据见 [本机 OmniDocBench 匹配代码](../../OmniDocBench/src/dataset/end2end_dataset.py#L2164) 和 [默认过滤项](../../OmniDocBench/src/dataset/end2end_dataset.py#L2259)。

## 已确认的验收口径

- **图片 subtype 判错，该图交付失败。** 即使文字、节点或连线都正确，该图主分也为 0；正确内容保留在诊断报告。单图失败计入图片专项，不单独否决整批。旧回放没采到 `sub_type` 时记「证据不足」，不判模型错类。
- **图表只评原图明示值。** 不要求估读，不设估读容差。原图没有标值的点不进入数值分母；有表、表头正确都不单独给主分。
- **确认误删即不通过。** 在冻结的保护样本上，只要开关切换导致一处必须保留的实质内容丢失，本批该版本就不通过验收。总分仍可展示用于定位，不能抵消误删。两版若都误删，同样都不通过。

保护 GT 事先标明应保留的正文、独立参考文献、签署提示及不应随视觉开关删除的原图和印刷图注。用同一份上游结果只切一个开关，对照最终交付；必须保留的内容在对照组完整、切换后实质丢失，并经源页复核，才确认误删。两组都缺是基础交付缺失，单报，也不算保护通过。对照或证据不完整时记「待核」，不宣称通过。报告并列展示质量分和验收结论。

## 首轮计分公式

| 分项 | 已确认的总分占比 | 主分试算 | 必须拉开分的 badcase |
| --- | ---: | --- | --- |
| 附录 | 25% | 按页检查开启保留和关闭无残留，两个都满足才记成功；先篇内算比例，再按篇平均 | 一处截断同时造成附录残留和独立参考文献误删 |
| 页眉页脚 | 25% | 按块计算开关交付 F1；开启正确且关闭无残留才记一次命中 | 开启漏识别、关闭残留、误删正文分别记录 |
| 图片与印章 | 25% | 图片逐图先判 subtype，正确后才计内容质量；印章单报内容后纳入专项 | 文字读对但类型判错、节点正确但连线错、合框后漏掉一张图的内容 |
| 图表 | 25% | 对可解析表中正确归属的明示数据项算 F1 | 完全漏转与有表却错列都不能拿正确数据分，失分原因分别记录 |

**专项总分 =（附录分 + 页眉页脚分 + 图片与印章分 + 图表分）÷ 4。** 各项为 0–100 分。F1 统一用 `100 × 2TP / (2TP + FP + FN)`：`TP` 是匹配且正确，`FP` 是错报，`FN` 是应交付而未正确交付。已知缺输出、有真值时是有效的 0 分。没有证据或分母时记 `null`。两版共用冻结 GT，四项齐全才汇总，不把缺项的权重分给其他项。代码实现的是首轮公式，校准用例不参与正式排名。

| 分项 | 从单条记录到专项分 |
| --- | --- |
| 附录 | 同一页开启完整且关闭彻底无残留记 1，否则记 0。每篇除以该篇已纳入的附录页数，再对有附录样本的文档等权平均，乘 100。 |
| 页眉页脚 | 每个 GT 边缘块开启正确且关闭无残留记 `TP`，否则记 `FN`；已复核范围内开启多报或写错的输出记 `FP`。所有评测页累加 `TP/FP/FN` 后算一个 F1。 |
| 图片与印章 | 图片类型错或确认未给出可归属的标签，单图为 0。类型正确的图片及印章先按内容得到单图分。组内取单图平均；文字图、流程图、照片、印章各占图片专项的 25%。有字与无字照片先分别平均，再各占照片组的一半。 |
| 图表 | 对可解析的生成表，按源图、系列、类别、值、单位计数据项命中。累加各图的 `TP/FP/FN` 再算 F1；未明示的系列不进分母，也不另给表头或转表分。 |

图片专项的四组及照片的两个子组需要都有可评分样本，避免仅凭某一类结果给出整个图片分。报告照常给出逐类 subtype 混淆矩阵、内容分和分母。保护验收独立于上表：已确认误删为 `fail`，有未核证据或专项无保护样本为 `pending`，冻结保护样本都完整才为 `pass`。这里的 `pass` 只指误删门槛，不等于全套质量达标。

## 附录

`1-3单元格内换行1.pdf` 第 15–34 页是附录，第 35 页独立参考文献应留。两版开启都返回第 35 页，关闭后都只交付至第 19 页。这个截断同时产生了 **第 15–19 页残留**和**第 35 页误删**。`3-1跨页重复表头.pdf` 第 25 页应随附录清除，因为参考文献属于附录。用这两页一起检验评测是否真的按人工边界判分。见[附录复核页](/private/tmp/pdf2text-gt-boundary.NXZp0L/index.html)。

| 检查 | 计分 |
| --- | --- |
| 开启保留 | 已标附录页里，预先标定的内容锚点均交付才算完整，避免只输出标题就通过。 |
| 关闭残留 | 对同一批附录页判定。保留了可归属的实质段落、图或表即计残留。 |
| 应留内容 | 按保护 GT 单报丢失页和文档数，区分两组都缺和关闭后丢失。确认误删触发验收失败，不以子分加权。没有附录的对照文档也可用于检查误删。 |

**附录分试算**：每篇以「开启完整且关闭无残留」的页数除以已确认附录页数，再按篇平均并乘 100，避免长附录支配分数。开启保留率、关闭残留率同时单报。正文与附录混页待标出块边界后，才纳入评分。

在先复核的三篇上，旧 IR 按页去留，两版均开启交付 **39/39** 页、关闭残留 **5/39** 页，并丢失 **1/52** 个应留页。第 35 页在同上游回放的开启组有、关闭组无，是误删门槛的校准例。即使把第 15–19 页都清干净，只要仍丢掉第 35 页，正式交付重现时仍不通过。

## 页眉页脚

`5-1双栏表格2.pdf` 第 1 页在两版开启组都交付 `RSC Advances` 和 `ROYAL SOCIETY OF CHEMISTRY`，关闭组这两段消失。源页刊头标志在开、关组均缺，标志和两段社名是三项不同的交付内容。`4-3扫描1.pdf` 第 5 页的 `(以下无正文)` 在两版开、关组均保留（`mineru.p5.0000`），用作正文保护正例。见[已审 GT 修订](../configs/legacy-129-block-overrides.json)。

| 检查 | 计分 |
| --- | --- |
| 开启交付 | 同页同来源匹配，核对归一化后的文案和印刷页码。标志需交付对应的可访问图像，社名文字不能代替标志。 |
| 关闭残留 | 在全部已标目标上评最终交付。关闭组剩下片段，或以正文形式输出同源边缘内容，都算残留。对确实在开启组观察到的块另报成对清除率，用来诊断过滤规则。 |
| 应留内容 | 核对预标的页边正文、签署提示等块。确认误删触发验收失败，不参与权重平均。 |

**页眉页脚分试算**：开启正确且关闭无残留的 GT 块记 `TP`，未满足的 GT 块记 `FN`；在已完整核对的范围内，额外交付的无来源或错误边缘项记 `FP`。计算 `100 × 2TP ÷ (2TP + FP + FN)`。允许拆并，每个 GT 块只计一次。分报开启漏识别、关闭残留和误删，并分别列出页眉、页脚、印刷页码和图片的有效分母。`source_type` 只用来追查识别、归类及过滤步骤。

刊头标志开关都缺，记一次未完成交付，关闭结果无残留，但不宣称过滤成功。若开启交付了标志、关闭仍留着它，也记一次未完成交付，原因改记残留。若边缘块开关都正确，但关闭误删了「以下无正文」，页眉页脚目标分可以满分，验收仍失败。

## 图片与印章

### 图片 subtype 是逐图通过条件

图内文字相同的两份输出也可能交付不同的结构。流程图错误标为 `text_image`，即使节点和连线内容碰巧都对，这张图也不通过。照片有招牌仍是照片，同时有文字提取要求。人工标注拆成**源图 subtype、可读性、应交付内容**三个字段，避免拿「有文字」代替图片类型。

| 试标类别 | 判定与内容要求 |
| --- | --- |
| 文字为主（`text_image`） | 文字、编号、标识等是图的主体。标可读的字段和所在区域。 |
| 照片（`natural_image`） | 以实景、设备、人像等照片为主体。分别标图内可读文字和无字状态，描述目前单列诊断。 |
| 流程或线路示意（`flowchart`） | 以流程步骤、连接或信号走向组织信息。标文字节点，同时给可确认的逻辑关系或连接标证据。图片中标注引线、示意箭头和真正步骤连接要分别审核。 |

这三个类别是本专项的首轮计分类。印章沿用已有 `seal`，单独评内容。复杂光谱图、地图、二维码等先标 `other` 或待审，保留审阅理由。若它们被明确误判成三个计分类之一，已审核的反例计进相应类别的 FP。`text_image` 等映射以实际服务字段确认。`mineru-vl-utils` 0.2.7 中，Image Analysis 返回 `class` 和 `sub_class`。`flowchart` 分支校验 Mermaid，随后通用图片分支将 `class` 写入 `image.sub_type`。`chart` 分支则写归一化的 `sub_class`。旧 IR 的视觉字段不含 `sub_type`，Mermaid 或描述只证明交付形态。依据为 `mineru_vl_utils/post_process/image_analysis_postprocess.py` 第 513 行及 `mineru_vl_utils/post_process/__init__.py` 第 100 行。见[旧 IR 适配字段](../src/doc_parse_bench/mineru_middle.py#L363)。

每张已定类的图用同一次解析的实际类型及来源对照 GT。**类型正确**才进入内容计分；**错类、确证漏标或未交付该源图的类型**，该图主分为 0；**旧 IR 丢字段、GT 类别未定**，记证据不足，既不等于 0 也不算通过。无字图可从同次结构化结果核对 subtype，无需强制生成描述来显示标签。最终内容仍按成品核对，不用结构化结果代替未交付的 Markdown。另报每类 F1、样本数和混淆矩阵，包括漏图及无标签，区分判错与漏交付。

合框先按同页的图号、子图编号或可区分的输出内容建立一对多对应。预测能分别标识两张源图的类型与内容时，两张分别计分。只有外框上的单个标签时，把它记为合框级预测，逐图未命中的标签计 FN。若原图本身是一幅含多个面板的复合图，按人工预先确认的图与子图层级计分。框大小和输出块数用于定位原因。

### 按源图类型计内容质量

| 源图类型 | 组内评分 |
| --- | --- |
| 文字为主 | 可读字段 F1。名称、日期、规格、型号等按源图标出的字段核对，排版归一化后做精确匹配。 |
| 流程或线路示意 | 有可审核关系的样本，**节点与标签 F1 占 60%**，**关系 F1 占 40%**。匹配已标节点后查端点、方向和子图归属。可确认只有局部标签的样本按事先登记的标签任务计分，关系不清楚的区域标待审。 |
| 照片 | 有字照片逐图评可读字段 F1。无字照片逐图检查原图是否可访问、是否编造图中文字，两项通过得 100，否则得 0。分别公布有字、无字的平均分和样本量，试标时两组都有有效样本可各占本组的 50%，避免大量无字照片冲淡漏字。描述中的场景事实初版另列。 |
| 印章 | 可辨认的机构名、专用章用途和编号等按字段算 F1，残章只纳入可确认字段，完整印章与残章分别公布分母。 |

**图片与印章怎样扣分**：类型正确的图片计其内容质量，类型错误的图片以 0 参与组内平均；印章沿用 `seal` 标注，单独核对内容。subtype F1 不重复加进主分。字段或关系错写算一个漏项和一个错报。首轮冻结清单只收入已完成 GT 的样本；缺预测证据时保留样本并暂空相应汇总分，不能剔除该样本来出总分。保留原始内容子分，以区分「只判错类型」和「类型错且漏内容」。

`4-2段落中带「图x-x」.pdf` 第 12 页的百分位图是正确转换的对照例。图块已人工改为 `chart` 并补齐标题和单位，按修订 GT 核对两版都命中 **5/5** 个明示值。

**图表分试算**：先确认最终交付的表格可解析，再按 `(源图或子图, 系列, 类别或横轴值, 数值, 单位)` 一对一匹配，只对冻结的明示值计 F1。正确关联记 `TP`，未交付正确值记 `FN`，已完整核对范围内的错列、错单位、错值与多报记 `FP`。同一错误项既未交付正确数据，也交付了错数据，分别记 `FN` 和 `FP`。汇总 `100 × 2TP ÷ (2TP + FP + FN)`，并按图及文档公布计数。单位和系列是命中条件，不是额外分。允许归一化等值格式（如 `79.88` 与 `79.880`），不允许为错值放宽容差。

允许合表、拆表和转置，条件是每项值能追溯到原图的相应系列和单位。同页的印刷原表不是该图的生成表，不能代替它得分。D-1 折线没有印出 `1310.9`，不拿同页原表的精确数字给曲线做 GT。先标出没有明示值的系列或数据项，不补估计值和容差；漏掉这些项不扣分，输出中的对应估计值最多作诊断。拿估计值覆盖已标明示值仍按明示值核对。只有估读点的图不进数值分母。光谱曲线等已确认保留为 `image` 的样本继续用来查误转。

用 10 个完整标好的明示值验分：没转出表为 **0**（10 个 `FN`），数字全放错列也为 **0**（10 个 `FN`、10 个 `FP`），只转对 8 个且无错报为 **88.89**，10 个都对为 **100**。表格可解析率、错列和错单位的数量、非图表误转率单报。这样保留「漏转」与「转出错误数据」的区别，又不会给错表比空输出更多的分。

图表关闭和图片关闭仍查生成结果清除、原图与印刷图注保留。旧回放的 `chart` 两种视觉分析均开启，`chart` / `image` 用来定位图表下游开关差异，`image` / `controls/image_off` 用同一次 B 上游结果复核图片生成内容清除。图片 subtype 和内容比较用 `image` 组，图表比较用 `chart` 组。

## 代码输入与运行

新入口 `evaluate-feature-rubric` 的[计分实现](../src/doc_parse_bench/feature_rubric.py)独立于 `evaluate-feature-matrix`。旧入口继续输出非空率、框匹配和开关回归指标。新入口**从按原页和源块对齐的证据计算分数**，不要求人工填写 F1、`TP` 或 `FN`。目前需人工复核来源并将输出展开成字段、表格数据项或开关去留证据；它不从任意 Markdown 自动找原页、推断 subtype，或把旧回放转成最终交付。

- **冻结 GT**：`schema_version` 为 `doc-parse-bench.feature-rubric-gt.v1`、`gt_version` 为 `legacy-129-feature-v3`。`split` 用 `calibration` 或 `evaluation`。`cases` 是列表，每条含唯一 `id`、`document_id`（`bc_001` 至 `bc_129`）、从 1 开始的物理 `page` 和 `feature`（`appendix`、`header_footer`、`image` 或 `chart`）。图片、图表和保护项的 `source_id` 是 v3 源块 ID 或明确的源内容锚点。
- **每版输出证据**：`schema_version` 为 `doc-parse-bench.feature-rubric-evidence.v1`，含 `model`、`gt_sha256`（GT 文件 SHA-256）、`config`（固定 `mineru_provider=mineru3`、`relevel_titles=true`、`title_rules=false`）、`stage`（`replay` 或 `final`）。`cases` 是按同一个 `id` 索引的对象。`captures[document_id][group]` 记录实际上游采集 ID 或哈希，成对组必须相同。附录用 `appendix` / `off`，页眉页脚用 `header_footer` / `off`，图片用 `image` / `controls/image_off`，图表用 `chart` / `image`。
- **空值语义**：已确认没有输出时写空列表、明确的 `missing` 或 `false`。无法核对则不填字段；对 subtype 而言，`"sub_type": null` 表示完整输出已查、确实缺标签，省略 `sub_type` 表示字段没采到。这两种状态不能互换。

| Case | GT 字段 | 输出证据字段 |
| --- | --- | --- |
| 附录页 | `anchors`：代表性内容锚点 ID | `on_anchors`：开启组确认保留的锚点；`off_residual`：关闭后是否有实质附录内容 |
| 页眉页脚页 | `blocks`：各块的 `id/type/text`，图片不需 `text` | `on_blocks`：实际片段 `id/source_id/text` 或 `image_available`；`off_residual_ids`：关闭后还在的 GT 块 ID。拆并后的片段按证据分配 ID；复核为多报时省略 `source_id`。 |
| 图片、印章 | `sub_type`、`fields`（`key/text`）；有已审关系时另有 `relations`（`from/to` 指向节点键） | 实际 `sub_type` 和标签来源 `subtype_id`；对应 `fields` 和 `relations`，每条有独立输出 `id`。已核定无字照片用空 GT `fields`，输出证据另需 `image_available`。估不准的字段不纳入已核范围。 |
| 图表 | `values`（`series/category/value/unit`）；`unscored` 写无明示值的 `series/unit` 或精确到 `category` | `table_status` 为 `parsed`、`missing` 或 `unparseable`。`parsed` 时提供可追溯的 `values`，每项有 `id`；保留实际列义和单位，不按 GT 替它纠错。数值用字符串；无单位用空字符串。 |
| 保护项 | `protected: true`，预先固定 `source_id` 及所属功能 | `on_state`、`off_state` 为 `complete`、`partial` 或 `missing`。对照一侧完整、切换后确认实质丢失计误删。两侧皆不完整暂不判过滤责任。 |

对齐必须保留核对范围内的所有输出，包括错报，不能只提交命中的内容。同页多张图共用一个预测外框时，可以提交来自同一个外框的不同输出项，代码禁止把同一个文字、连线、数据项或标签 ID 重复给两个源图计分。应将无法归属的项记录为待复核，而不是把它复制给多个 GT。正式保护检查用实际成品的源内容对照，`captures` 只检查证据声明使用了同一次上游采集，不自动验证 Markdown 是如何生成的。

可拿[校准 GT](../tests/fixtures/feature_rubric_129/gt.json)和 [ft](../tests/fixtures/feature_rubric_129/ft.json)、[origin](../tests/fixtures/feature_rubric_129/origin.json) 的旧回放证据直接试算：

```bash
done
```
