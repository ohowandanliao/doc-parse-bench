# 四功能评分口径

四专项均为 0–100，各占总分 25%。各模型在同一批 PDF 上共用冻结的计分清单，以经过来源核对的实际成品证据评分。

## 计分清单

- `schema_version` 为 `doc-parse-bench.feature-rubric-gt.v1`。`gt_version` 由该批标注的版本决定，例如 `operations-manuals-2026-11`。正式范围用 `split=evaluation`，校准范围用 `split=calibration`。
- `cases` 是列表。每条含唯一 `id`、稳定的 `document_id`、从 1 开始的物理 `page` 及 `feature`。各专项名称为 `appendix`、`header_footer`、`image`、`chart`。
- 图表、图片及保护项用 `source_id` 指向源块或原文锚点。页眉页脚按页记录 `blocks`，附录页记录 `anchors`，视觉字段见[补标流程](annotation.md)。`protected: true` 的记录只参与误删门槛。
- 预测 evidence 按同一个 `id` 索引，保存 `gt_sha256`。评分入口校验清单哈希、证据归属以及重复 ID。评价范围和分母来自冻结清单。

成品归属、开关对照和 evidence 字段见[评测输入](inputs.md)。

## 固定公式

| 专项 | 主分 | 聚合方式 |
| --- | --- | --- |
| 附录 | 一页所有预标锚点在开启组交付，且关闭组无实质附录残留，得 100；否则 0 | 先篇内按页平均，再对篇等权平均 |
| 页眉页脚 | GT 块开启交付正确且关闭无残留记 TP；未满足记 FN；已审核范围内错报或额外输出记 FP | 全部已纳入块累加，`100 × 2TP / (2TP + FP + FN)` |
| 图片与印章 | 图片 subtype 正确后计内容；类型错或确证缺标签，单图主分为 0；印章直接计字段内容 | 文字图、流程图、照片、印章各 25%；有字／无字照片在照片组内各 50% |
| 图表 | 在同一源图内按行标签和整列一对一匹配明示值 | `100 × 命中明示值数 / GT 明示值数` |

文字图、有字照片和印章按字段 F1。无字照片要求原图可访问且没有编造文字。已标关系的流程图按 `60% 字段 F1 + 40% 有向关系 F1`，边端点必须能归属到文字正确的节点。只登记文字的图按文字计分。

总分为四专项分的算术平均，要求 `split=evaluation`、`stage=final` 且四项都有完整证据。单独补图表的批次可出图表分。图片批次按实际类型出分层结果，图片专项总分需要文字图、流程图、有字照片、无字照片和印章均有完整证据。缺项和未满足条件的总分记 `null`。校准或回放发布分项和诊断。

## 文本、数值与归属

- 文本只做 Unicode NFKC 和空白归一化，不做同义词猜测或标点容错。因此 `PE/PH`、`–/-` 保持可区分。
- 数字按精确十进制比较。`79.88` 与 `79.880` 等值，数值前缀 `~` 表示估读。
- 图表证据记录生成表的原文、实际列名和单位。同页印刷表是另一个来源块。
- 来源按原 PDF、物理页、源块／内容锚点对齐。允许审核后的拆并匹配，但同一文字、连线、数值或 subtype 输出 ID 不能借给两个源图重复计分。
- 父图和子图的 subtype 分别归到实际分析范围。
- 流程分支标签的文字和归属单列诊断。有向关系主分使用已冻结的端点与方向。

## 图表明示值命中率

评测适配层先将成品表格归到源图。评分时用年份或类别对齐行，再对 GT 数据列和实际数据列做一对一配对，取命中数最多的配对。图表分支持整列重排，将 `2019` 与 `2019年` 视为同一行。

百分比明示值兼容 `7.46`、`7.460%` 和全角写法。显示数值仍按精确十进制比较。单元格自身带 `%` 时，只能与百分比明示值配对。

实际列号 `column_id` 将单元格与自己的表头、单位绑定。通用表头和简称可以通过数值匹配，已知系列名或明确单位与配对列冲突时，报告列级证据和涉及的图。漏表、漏值和串行串列会降低命中率。报告同时给出未匹配的输出单元格数量和可解析表格数量。GT 的计分范围来自图上明示的值。

## 空输出、未采到与失败归因

| 状态 | 证据写法 | 评分含义 |
| --- | --- | --- |
| 完整成品已核对，确实没有字段 | `fields: []` | 已知漏项，可计 0 |
| 实际类型已核对，确实没有 subtype | `sub_type: null` | 图片标签交付失败，单图主分 0；不自动判为模型错分类 |
| 旧 IR 丢标签或没有对应分析单位响应 | 省略 `sub_type` 或相应字段 | `evidence_missing`，不能填成 0 |
| 已确认没有可解析图表 | `table_status: missing/unparseable` | 此图的明示值命中数为 0 |
| 未采到图表成品 | 省略 `table_status` | 证据不足 |
| 未调用、超时或请求失败 | 在采集日志记录实际状态 | 先区分工程原因；不能从日志自动推断模型读图能力为 0 |

评分对象是声明范围内的最终交付。归因时，按原始响应、补偿追踪及实际成品定位分析缺失的阶段。

## 误删门槛

保护项必须使用同一上游采集结果的开关对照。对照一侧完整，切换后实质内容部分或全部丢失，记确认误删；任一确认误删都使该批保护门槛失败，与质量分独立。两侧都缺是基础缺失，仍待核；证据或保护范围不足不判通过。

报告中 `deletion_gate.status=calibration_only` 表示该次并非正式验收；`observed_status=fail` 仍明确显示已有校准误删，不能用前一个字段掩盖后一个。

## 可复现入口与输出

在仓库根目录评分。

```sh
.venv/bin/docbench evaluate-feature-rubric \
  --gt /path/to/batch/rubric-evaluation-gt.json \
  --pred /path/to/model/evidence.json \
  --output /path/to/new-empty-score-directory
```

`python -m doc_parse_bench.feature_evaluation.feature_score_cli score` 调用同一实现。每次使用空输出目录。产物如下。

- `metrics.json` 记录分数、覆盖率、分母、分层结果及误删状态。
- `per_case.json` 记录逐案得分、图表列匹配、图片类型和缺证据原因。
- `pending_cases.json` 记录待补证据。
- `report.md` 展示分数表、报告诊断及逐案结果。
- `provenance.json` 记录 GT 版本、GT 和证据哈希、评分源码和契约哈希、配置及证据阶段。
