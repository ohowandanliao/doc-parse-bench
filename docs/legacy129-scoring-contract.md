## 固定公式

| 专项 | 主分 | 聚合方式 |
| --- | --- | --- |
| 附录 | 一页所有预标锚点在开启组交付，且关闭组无实质附录残留，得 100；否则 0 | 先篇内按页平均，再对篇等权平均 |
| 页眉页脚 | GT 块开启交付正确且关闭无残留记 TP；未满足记 FN；已审核范围内错报或额外输出记 FP | 全部已纳入块累加，`100 × 2TP / (2TP + FP + FN)` |
| 图片与印章 | 图片 subtype 正确后计内容；类型错或确证缺标签，单图主分为 0；印章直接计字段内容 | 文字图、流程图、照片、印章各 25%；有字／无字照片在照片组内各 50% |
| 图表 | `(源图, 系列, 类别, 明示值, 单位)` 一对一匹配；错值、错列或错单位同时产生 FN 和 FP；确认漏表只有 FN | 累加已标范围的明示项，算内容 F1 |

图片内容：文字图、有字照片和印章按字段 F1；无字照片要求原图可访问且未编造文字；已标关系的流程图按 `60% 字段 F1 + 40% 有向关系 F1`，边端点必须能归属到文字正确的节点。GT 仅登记文字的线路图只评登记范围，不能把文字分叫做完整结构分。

总分为四专项分的算术平均。任一专项缺证据，则该专项及总分为 `null`；不重新分配权重。`split=calibration` 或 `stage=replay` 时只出校准分项与诊断，总分保持 `null`。质量通过阈值尚未确定，本次不新增阈值。

## 文本、数值与归属

- 文本只做 Unicode NFKC 和空白归一化，不做同义词猜测或标点容错。因此 `PE/PH`、`–/-` 保持可区分。
- 数字用精确十进制比较；允许等值格式，例如 `79.88 = 79.880`，允许百分号与 `%` 单位配套归一化；不估读，不放宽数值误差。
- 输出表的系列及单位沿用实际表列语义；不拿 GT 修正 `Value` 等泛称表头，不从同页印刷原表补图表答案。若以后允许图注辅助系列归属，需要另行确认并统一重评。
- 来源按原 PDF、物理页、源块／内容锚点对齐。允许审核后的拆并匹配，但同一文字、连线、数值或 subtype 输出 ID 不能借给两个源图重复计分。
- 父图和子图的 subtype 分别归属。子面板有 `flowchart` 标签不能给整个父图提供标签。Origin 仅为对照。
- 流程分支标签的文字与所属分支都需要复核。当前校准 GT 的有向边记录仅含端点，分支绑定另有诊断；不得宣称评分器已覆盖任意分支交换错误，未冻结的绑定关系也不能临时补入正式分母。

## 空输出、未采到与失败归因

| 状态 | 证据写法 | 评分含义 |
| --- | --- | --- |
| 完整成品已核对，确实没有字段 | `fields: []` | 已知漏项，可计 0 |
| 实际类型已核对，确实没有 subtype | `sub_type: null` | 图片标签交付失败，单图主分 0；不自动判为模型错分类 |
| 旧 IR 丢标签或没有对应分析单位响应 | 省略 `sub_type` 或相应字段 | `evidence_missing`，不能填成 0 |
| 已确认没有可解析图表 | `table_status: missing/unparseable` | 按漏交付计算 FN；原因分别保留 |
| 未采到图表成品 | 省略 `table_status` | 证据不足 |
| 未调用、超时或请求失败 | 在采集日志记录实际状态 | 先区分工程原因；不能从日志自动推断模型读图能力为 0 |

评分对象是已声明范围的交付，归因另做。已知最终交付缺失可以判交付失败；只有分析单位有实际响应，才能核对该单位模型内容。历史 FT 的 `image_block` 缺口和 P2T 丢标签不能全部归为训练问题。

## 误删门槛

保护项必须使用同一上游采集结果的开关对照。对照一侧完整，切换后实质内容部分或全部丢失，记确认误删；任一确认误删都使该批保护门槛失败，与质量分独立。两侧都缺是基础缺失，仍待核；证据或保护范围不足不判通过。

报告中 `deletion_gate.status=calibration_only` 表示该次并非正式验收；`observed_status=fail` 仍明确显示已有校准误删，不能用前一个字段掩盖后一个。

## 可复现入口与输出

仓库内用现有环境，无需安装新依赖：

```sh
.venv/bin/python -m doc_parse_bench.feature_score_cli score \
  --gt artifacts/legacy-features-20261119/rubric-pilot-gt.json \
  --pred experiments/legacy129-subimage-20261123/calibration-evidence/3.1-ft.json \
  --output /tmp/legacy129-ft-scores-new
```

`3.1-origin.json` 用相同命令、不同空目录评分。内网交接包 `evaluation/` 提供同一源码和标准库 CLI，不需要本仓库依赖或 MinerU：

```sh
python3 score.py score --gt gt/rubric-pilot-gt.json \
  --pred evidence/3.1-ft.json --output /tmp/legacy129-ft-scores-new
python3 score.py template --gt gt/rubric-pilot-gt.json \
  --model 3.1-ft --output /tmp/ft-evidence-blank.json
```

空模板只带 case ID、配置和 GT 哈希，绝不复制 GT 字段或明示值作为预测。实际证据字段及开关配对见 [详细评分实现说明](feature-evaluation-129-rubric.md)。配对名称中历史 `chart` 是图片／图表双开，不是独立 chart-only。四种视觉组合的兼容性验收必须另存，不能用历史分数证明 chart-only 已通过。

每次产物包含：

- `metrics.json`：分数、0–100 的证据覆盖率、真实 GT 分母、分层结果、`overall_blockers`、误删状态。
- `per_case.json`：逐案主分、内容诊断、标签状态、TP/FP/FN 和缺证据原因。
- `pending_cases.json`：仍待补的证据清单；用于补证据，不得据此缩减 GT 分母。
- `report.md`：直接可读的分数及逐案表。
- `provenance.json`：GT、证据、评分源码与契约哈希，目标配置、实际标题重排声明及证据阶段。
